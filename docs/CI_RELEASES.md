# Сборки и обновления (для разработчика)

В проекте две независимые автоматизации в разделе **GitHub → Actions**.

## DEV Build (Windows)

Запускается при Pull Request в `main`, push в `main`, `dev`,
`dev/**`, `feature/**`, а также вручную (Run workflow).

Сборка проходит на Windows x64. Результат находится в **Actions → нужный
запуск → Artifacts**: архив `rosreestr_parser_dev.zip` и файл SHA256.
GitHub упаковывает Artifacts в дополнительный ZIP — сначала распакуйте
его, затем `rosreestr_parser_dev.zip`.

В DEV-заголовке программы указано `DEV` и короткий SHA коммита.
В DEV-конфигурации отключена проверка стабильных обновлений.
DEV не создаёт GitHub Release и не меняет `latest.json`.

**Запускайте DEV в отдельной папке.** Не накладывайте его поверх
установленной версии, содержащей рабочие реестры и профили.

## Stable Release (Windows)

Выпуск запускается **только вручную** из ветки `main`.

1. Проверьте DEV EXE на своём Windows: запуск, Chrome, сохранение Excel,
   ключевые сценарии ОСС/СНТ. Автоматическая сборка не заменяет эти тесты.
2. В исходниках поднимите `APP_TITLE` и `APP_VERSION_CODE` (например,
   `V1.4`, `14`). Внесите изменение в `main` через PR.
3. Откройте **Actions → Stable Release (Windows) → Run workflow**.
   Выберите `main`, введите tag `v1.4` и перечень изменений.
4. Workflow сверяет номер версии с исходниками и предыдущим
   `latest.json`, собирает portable EXE, проверяет содержимое ZIP,
   конфигурацию, SHA256, публикует `rosreestr_parser.zip` как GitHub
   Release и **только после успешной публикации** обновляет
   `latest.json` в `main`.
5. Проверьте новый GitHub Release и автообновление из старой версии.

Если сборка/проверка не удалась, обновления для пользователей нет.
Если Release уже опубликован, но запись `latest.json` завершилась ошибкой,
не запускайте заново workflow с этим же тегом: сначала проверьте
состояние Release и восстановите только манифест.

Для публикации GitHub Actions требуется `contents: write`. Если
включена защита `main`, потребуется разрешить публикацию манифеста
для `github-actions[bot]` или заменить прямой push на PR.

## Резервная локальная сборка

Остаются `00_SETUP.bat`, `01_RUN.bat` и `02_BUILD_EXE.bat`.
Релизный архив локально формируется точно так же. В CI BAT запускается
без интерактивной остановки на `pause`.

## Внимание: старый локальный config.json

Ранее файл `config.json` ошибочно отслеживался в Git. Теперь он удалён
**из актуальной версии репозитория**, добавлен в `.gitignore`, а сборка
использует только `config.example.json`.

**До `git pull` / смены ветки в вашей старой рабочей копии
сохраните `C:\rosreestr-parser\config.json` за пределами репозитория.**
Git может удалить отслеживаемую локальную копию при получении коммита,
который удалил файл. После обновления кода верните свой `config.json` —
он останется локальным и больше не будет попадать в git.

Удаление файла из актуальной ветки не удаляет его из истории коммитов.
Если в истории когда-либо были пароли или токены, их надо отдельно
отозвать. История Git в рамках этой настройки не переписывается.
